## 컬렉션 3대장 구조와 특징의 이해

### 컬렉션 프레임워크란
+ 여러 데이터를 담고 꺼내는 **자료구조를 표준 인터페이스로 통일해 둔 라이브러리**
+ 배열과 달리 크기가 고정되지 않고, 추가·삭제·검색 메서드를 이미 제공함
+ 핵심은 **인터페이스와 구현체의 분리**
    - `List`, `Set`, `Map`은 "무엇을 할 수 있는지"만 정의한 인터페이스
    - `ArrayList`, `HashSet`, `HashMap`은 "어떻게 할지"를 정한 구현체
    - 그래서 변수는 인터페이스 타입으로 선언하고, 구현체만 갈아끼우는 게 관례
        ```java
        List<String> list = new ArrayList<>();  // O: 나중에 LinkedList로 교체 가능
        ArrayList<String> list2 = new ArrayList<>(); // X: 구현체에 묶임
        ```
    - 이게 [다형성](../04-자바와-객체지향-프로그래밍/다형성.md)이 실제로 쓰이는 가장 흔한 사례

### 상속 구조
```
        Iterable
           │
       Collection            Map (Collection을 상속하지 않음)
      ┌────┴────┐             │
    List       Set        ┌───┴────┬─────────┐
     │          │      HashMap  TreeMap  LinkedHashMap
 ArrayList   HashSet
 LinkedList  LinkedHashSet
 Vector      TreeSet
```
+ `List`와 `Set`은 `Collection`을 상속 → `add()`, `size()`, `iterator()` 같은 공통 메서드를 공유
+ **`Map`은 `Collection`이 아님**
    - `Collection`은 요소 하나를 다루는데, `Map`은 키-값 **쌍**을 다뤄서 메서드 모양이 안 맞음
    - 대신 `keySet()`, `values()`, `entrySet()`으로 `Collection` 뷰를 꺼내 쓸 수 있음
+ `Collection`이 `Iterable`을 상속하므로 향상된 for문(`for-each`)을 쓸 수 있음

### 자바의 다양한 컬렉션
+ List
    - 순서가 있는 데이터 저장 구조 (인덱스 기반)
    - 중복 데이터 허용
    - ArrayList, LinkedList, Vector 등이 있음
        ```java
        List<String> list = new ArrayList<>();
        list.add("A");
        list.add("B");
        list.add("A"); // 중복 허용
        System.out.println(list);    // 출력: [A, B, A]
        System.out.println(list.get(0)); // 출력: A (인덱스로 접근)
        ```
+ Set
    - 중복을 허용하지 않는 데이터 저장 구조
    - 순서를 보장하지 않음
    - HashSet, TreeSet 등이 있음
        ```java
        Set<String> set = new HashSet<>();
        set.add("A");
        set.add("B");
        boolean added = set.add("A"); // 중복 불가능
        System.out.println(added);    // 출력: false (추가 실패를 반환값으로 알려줌)
        System.out.println(set);      // 출력: [A, B] (순서 보장되지 않음)
        ```
+ Map
    - 키(Key)-값(Value) 형태로 데이터를 저장하는 구조
    - Key는 중복 불가능, Value는 중복 가능
    - HashMap, LinkedHashMap, TreeMap 등이 있음
        ```java
        Map<Integer, String> map = new HashMap<>();
        map.put(1, "A");
        map.put(2, "B");
        String old = map.put(1, "C"); // 같은 Key 덮어쓰기
        System.out.println(old);      // 출력: A (덮어쓰기 전 값을 반환)
        System.out.println(map);      // 출력: {1=C, 2=B}
        ```

### 셋의 차이를 한 표로
| | List | Set | Map |
|---|---|---|---|
| 저장 단위 | 값 | 값 | 키-값 쌍 |
| 중복 | 허용 | 불가 | 키는 불가, 값은 허용 |
| 순서 | 인덱스로 보장 | 구현체에 따라 다름 | 구현체에 따라 다름 |
| 인덱스 접근 | `get(i)` 가능 | 불가 | 불가 (키로 접근) |
| 상위 인터페이스 | `Collection` | `Collection` | 없음 |
| 대표 용도 | 순서대로 쌓기 | 중복 제거·포함 검사 | 키로 빠르게 찾기 |

### 어떤 걸 언제 쓰나
+ **순서대로 쌓고 인덱스로 꺼낸다 → `List`**
    - 대부분 `ArrayList`. 조회가 압도적으로 많고 구현이 단순함
    - 앞·중간 삽입/삭제가 매우 잦으면 `LinkedList`를 고려 (다만 실무에서 이득 보는 경우는 드묾)
    - `Vector`는 모든 메서드에 `synchronized`가 붙은 옛날 클래스. 새 코드에서는 쓰지 않음
+ **"이미 있는지" 확인하거나 중복을 없앤다 → `Set`**
    - `list.contains()`는 요소를 하나씩 다 훑지만(O(N)), `set.contains()`는 해시로 한 번에 찾음(O(1))
    - 중복 제거는 `new HashSet<>(list)` 한 줄이면 끝
+ **키로 값을 찾는다 → `Map`**
    - "ID로 사용자 찾기", "단어별 개수 세기"처럼 **무언가를 기준으로 조회**하는 모든 상황

### List의 구현체 비교
| | ArrayList | LinkedList | Vector |
|---|---|---|---|
| 내부 구조 | 배열 | 이중 연결 리스트 | 배열 |
| 인덱스 조회 | O(1) | O(N) | O(1) |
| 중간 삽입·삭제 | O(N) | 노드를 알면 O(1) | O(N) |
| 동기화 | X | X | O (메서드마다 `synchronized`) |
| 언제 쓰나 | 기본 선택 | 앞뒤 삽입·삭제가 잦을 때 | 쓰지 않음 (레거시) |

+ `ArrayList`는 내부 배열이 꽉 차면 더 큰 배열을 만들어 복사함 (자동 확장)
    - 담을 개수를 미리 알면 `new ArrayList<>(1000)`처럼 초기 용량을 주는 게 유리
+ `LinkedList`는 인덱스 조회가 느리다는 점이 핵심
    - `for (int i = 0; i < list.size(); i++) list.get(i)` 같은 코드는 `LinkedList`에서 O(N²)이 됨

### 컬렉션이 "같음"을 판단하는 방법
+ `Set`의 중복 판정, `Map`의 키 비교는 모두 `equals()`와 `hashCode()`에 의존함
+ **해시 기반 컬렉션(`HashSet`, `HashMap`)의 판정 순서**
    1. `hashCode()`로 저장 위치(버킷)를 계산
    2. 그 위치에 있는 요소들과 `equals()`로 비교
+ 그래서 **`equals()`를 재정의하면 `hashCode()`도 반드시 같이 재정의**해야 함
    - 안 하면 논리적으로 같은 객체가 서로 다른 버킷에 들어가 중복 저장됨
        ```java
        class User {
            String id;
            User(String id) { this.id = id; }
            @Override public boolean equals(Object o) {
                return o instanceof User u && id.equals(u.id);
            }
            // hashCode()를 재정의하지 않았다!
        }

        Set<User> set = new HashSet<>();
        set.add(new User("kim"));
        set.add(new User("kim"));
        System.out.println(set.size()); // 출력: 2 (중복 제거 실패)
        ```
    - `hashCode()`도 `Objects.hash(id)`로 재정의하면 `1`이 됨
+ `record`를 쓰면 `equals()`/`hashCode()`가 자동 생성되므로 이 실수 자체가 사라짐

### 제네릭과 타입 안정성
+ 컬렉션은 내부적으로 `Object`를 담기 때문에, 제네릭 `<>`으로 담을 타입을 못 박아 둠
    ```java
    List<String> list = new ArrayList<>();
    list.add(10); // 컴파일 에러 - 실행 전에 잡힘

    List raw = new ArrayList();  // 로 타입(raw type)
    raw.add("A");
    raw.add(10);
    String s = (String) raw.get(1); // 컴파일은 통과, 실행 중 ClassCastException
    ```
+ 기본형은 담을 수 없어서 래퍼 클래스를 씀 (`List<int>` X, `List<Integer>` O)
    - 오토박싱이 자동으로 변환해주지만, 대량 반복에서는 객체 생성 비용이 붙음

### 자주 하는 착각
+ "`Map`도 `Collection`의 일종이다"
    - 아님. `Map`은 `Collection`을 상속하지 않는 별도 계층. 요소 단위가 달라서 메서드를 공유할 수 없음
+ "`Set`은 순서가 없으니 매번 출력 순서가 바뀐다"
    - 순서를 **보장하지 않을** 뿐, 같은 데이터·같은 구현체면 보통 같은 순서로 나옴. 그 순서에 의존하는 코드를 쓰면 안 된다는 뜻
+ "`Arrays.asList()`로 만든 리스트에 `add()`를 할 수 있다"
    - 고정 크기 뷰라서 `add()`/`remove()`는 `UnsupportedOperationException`. `List.of()`는 아예 전부 불변
+ "`LinkedList`가 `ArrayList`보다 삽입이 빠르다"
    - 위치를 이미 알고 있을 때만. 인덱스로 찾아가는 비용(O(N))이 삽입 비용보다 큰 경우가 대부분
+ "for-each 안에서 `remove()`를 해도 된다"
    - `ConcurrentModificationException`이 남. `Iterator.remove()`나 `removeIf()`를 써야 함
        ```java
        list.removeIf(s -> s.startsWith("A")); // 안전한 방법
        ```
+ "`HashMap`은 스레드 세이프하다"
    - 아님. 멀티스레드 환경에서는 `ConcurrentHashMap`을 씀
