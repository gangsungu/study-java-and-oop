## 자바의 OOP

객체지향 개념 자체는 [객체 지향이란](../01-객체지향이란/객체지향이란.md) 문서에서 정리했다.
이 문서는 그 개념을 **자바 문법이 어떤 규칙으로 받아내는지**에 초점을 맞춘다.

### 객체지향 프로그래밍의 핵심 키워드 간단 정리
+ 클래스(Class)
    - 객체를 생성하기 위한 설계도 또는 틀
    - 속성(멤버 변수)과 동작(메서드)을 포함하여 객체를 정의함
+ 생성자(Constructor)
    - 객체가 생성될 때 자동으로 호출되어 초기화를 담당하는 특별한 멤버
    - 클래스 이름과 동일하며, 반환 타입이 없음
+ 상속(Inheritance)
    - 부모 클래스의 속성과 메서드를 자식 클래스가 물려받는 개념
    - 코드 재사용성을 높이고, 유지보수를 쉽게 할 수 있음
    - extends 키워드를 사용하여 부모 클래스를 상속받음
    - 필요에 따라 메서드를 재정의(오버라이딩)할 수 있음
+ 오버라이딩(Overriding)
    - 부모 클래스의 메서드를 자식 클래스에서 재정의하는 것
    - 메서드의 이름과 매개변수가 같아야 하고, 반환 타입은 같거나 그 하위 타입이어야 함
    - 다형성을 구현하는 핵심 개념
+ 오버로딩(Overloading)
    - 같은 이름의 메서드를 매개변수를 다르게 하여 여러 개 정의하는 것
    - 매개변수의 개수, 타입, 순서 중 하나라도 다르면 같은 이름의 메서드를 여러 개 만들 수 있음
+ super 키워드
    - 부모 클래스의 멤버에 접근할 때 사용
    - super()는 부모 클래스의 생성자를 호출할 때 사용
    - 오버라이딩된 메서드에서 부모 메서드를 호출할 때도 사용 가능

### 클래스와 객체
+ 클래스는 설계도, 객체(인스턴스)는 그 설계도로 찍어낸 실체
    - 클래스는 JVM에 **한 번만** 로딩되고, 객체는 `new` 할 때마다 힙에 새로 만들어짐
+ 클래스의 멤버는 필드, 메서드, 생성자, 초기화 블록, 중첩 클래스
+ `new` 가 하는 일 순서
    - ① 힙에 객체 공간 확보 → ② 모든 필드를 **기본값**으로 초기화 → ③ 필드 초기화식·초기화 블록 실행 → ④ 생성자 본문 실행 → ⑤ 참조 반환
+ 필드는 기본값이 자동으로 들어가지만 **지역 변수는 들어가지 않음**
    - 필드: 정수 `0`, 실수 `0.0`, `boolean`은 `false`, 참조형은 `null`
    - 지역 변수는 초기화하지 않고 읽으면 컴파일 에러 (`variable x might not have been initialized`)
    - 힙은 JVM이 0으로 밀어주지만 스택 프레임은 그렇지 않기 때문

### 생성자
+ 문법 규칙
    - 클래스 이름과 완전히 같아야 하고, 반환 타입을 쓰지 않음 (`void`도 안 됨)
    - **상속되지 않음** — 자식은 부모 생성자를 물려받지 않고 `super(...)`로 호출만 함
    - 오버로딩 가능 (매개변수가 다른 생성자를 여러 개 둘 수 있음)
+ 반환 타입을 붙이면 생성자가 아니라 그냥 메서드가 됨
    - 컴파일 에러가 나지 않아서 찾기 어려운 실수

    ```java
    class Cat {
        private String name;

        void Cat(String name) {   // void를 붙이는 순간 생성자가 아님
            this.name = name;
        }
    }
    // new Cat("나비") → 컴파일 에러 (인자 있는 생성자가 없음)
    // new Cat()       → 컴파일러가 만든 기본 생성자가 호출되고 name은 null
    ```

+ 기본 생성자 자동 생성, 자동 `super()` 삽입 규칙은 [객체 지향이란 — 상속과 생성자 규칙](../01-객체지향이란/객체지향이란.md#상속과-생성자-규칙) 참고
+ 초기화 실행 순서 (전체)
    - ① 부모 static 필드·static 초기화 블록 → ② 자식 static 필드·static 초기화 블록 (클래스당 최초 1회)
    - ③ 부모 인스턴스 필드·인스턴스 초기화 블록 → ④ 부모 생성자 본문
    - ⑤ 자식 인스턴스 필드·인스턴스 초기화 블록 → ⑥ 자식 생성자 본문
    - static은 **클래스당 한 번**, ③~⑥은 **객체를 만들 때마다** 실행됨
    - 필드 초기화식과 초기화 블록은 따로 도는 것이 아니라 **작성한 순서대로 섞여서** 실행됨
+ 생성자 안에서 오버라이딩 가능한 메서드를 호출하지 말 것
    - 부모 생성자가 도는 시점에는 자식 필드가 **아직 초기화되기 전**임

    ```java
    class Parent {
        Parent() {
            init();          // 위험: 자식이 재정의한 init()이 실행됨
        }
        void init() {}
    }

    class Child extends Parent {
        private String name = "바둑이";

        @Override
        void init() {
            System.out.println(name.length());   // NullPointerException
        }
    }
    // new Child() → Child() → super() → Parent() → Child.init()
    // 이 시점에 name = "바둑이" 대입은 아직 실행되지 않아 null
    ```

    - 확장 지점으로 열 생각이 없는 메서드는 `private`이나 `final`로 막는 것이 안전함

### 상속
+ 자바는 **단일 상속**만 허용 (`extends`는 하나), 인터페이스는 여러 개 구현 가능
    - 같은 멤버를 여러 부모에게 물려받으면 어느 쪽인지 정할 수 없기 때문 (다이아몬드 문제)
+ 무엇이 상속되고 무엇이 안 되는지

    | 대상 | 상속 | 비고 |
    |------|:---:|------|
    | public / protected 멤버 | ⭕ | 다른 패키지의 자식에서 protected는 조건부 |
    | default 멤버 | ⚠️ | 같은 패키지일 때만 접근 가능 |
    | private 멤버 | ❌ | 객체 안에는 존재하지만 자식 코드에서 접근 불가 |
    | 생성자 | ❌ | `super(...)`로 호출만 함 |
    | 초기화 블록 | ❌ | 부모 것은 부모 생성자 과정에서 실행됨 |
    | static 멤버 | ⭕ | 재정의는 오버라이딩이 아니라 **하이딩** |

+ `final` 클래스는 상속할 수 없음
    - `String`, `Integer` 같은 값 성격의 클래스가 대표적. 값이 바뀌지 않는다는 보장을 자식이 깨뜨리지 못하게 함
+ 상속보다 **조합(Composition)** 을 먼저 고려
    - is-a 관계일 때만 상속함. "Car is-a Engine"은 틀렸고 "Car has-a Engine"이 맞음
    - 상속은 부모의 **구현**에 자식이 묶이는 가장 강한 결합이라, 부모를 고치면 자식이 조용히 깨짐
    - 관련 원칙은 [객체지향 설계원칙](../02-객체지향-설계원칙/객체지향-설계원칙.md) 문서 참고

### 오버라이딩
+ 성립 조건
    - 이름과 **매개변수 목록(타입·개수·순서)이 완전히 같아야 함**
        + 하나라도 다르면 오버라이딩이 아니라 오버로딩(또는 그냥 새 메서드)이 됨
    - 반환 타입은 같거나 **부모 반환 타입의 하위 타입** (공변 반환 타입, Java 5+)
    - 접근 제어자는 부모보다 **좁힐 수 없음** (넓히는 것은 가능)
    - checked 예외는 부모가 선언한 것보다 **넓게 던질 수 없음** (unchecked 예외는 제한 없음)

    ```java
    class Animal {
        protected Animal reproduce() throws IOException { return new Animal(); }
    }

    class Cat extends Animal {
        @Override
        public Cat reproduce() throws FileNotFoundException {   // 셋 다 허용됨
            return new Cat();
        }
        // public                : protected보다 넓힘             → OK
        // Cat                   : Animal의 하위 타입 (공변 반환)  → OK
        // FileNotFoundException : IOException의 하위 타입         → OK
    }
    ```

+ 오버라이딩할 수 없는 것

    | 대상 | 결과 |
    |------|------|
    | `static` 메서드 | **하이딩** — 재정의처럼 보이지만 참조 변수의 **선언 타입** 기준으로 호출됨 |
    | `final` 메서드 | 문법으로 금지 (컴파일 에러) |
    | `private` 메서드 | 자식에게 보이지 않으므로 이름이 같아도 **완전히 별개의 새 메서드** |

+ `@Override`
    - 필수는 아니지만, 붙이면 컴파일러가 "실제로 부모 메서드를 재정의하는 게 맞는지" 검사해줌
    - 재정의한 줄 알았는데 새 메서드가 만들어진 버그를 막아줌

    ```java
    class Cat {
        // @Override 를 안 붙이면 컴파일은 통과하지만 Object.equals()를 재정의한 게 아님
        public boolean equals(Cat other) { ... }   // 오버로딩이 되어버림
    }
    // → HashMap이나 List.contains()는 equals(Object)를 호출하므로 전혀 동작하지 않음
    ```

### 오버로딩
+ 성립 조건: 매개변수의 **타입·개수·순서** 중 하나 이상이 달라야 함
+ 오버로딩이 아닌 것 (전부 컴파일 에러)
    - 반환 타입만 다른 경우
    - 매개변수 **이름만** 다른 경우
    - 던지는 예외만 다른 경우
    - 이유: 자바는 **이름 + 매개변수 목록**(시그니처)으로만 메서드를 구분함. 호출부 `print(1)`만 봐서는 어느 쪽인지 정할 수 없음
+ 어떤 메서드가 선택되는지 — **컴파일 시점**에 3단계로 결정됨
    - 1단계: 형변환 없이, 또는 **확대 형변환**(int → long)으로 맞는 것
    - 2단계: **오토박싱/언박싱**까지 허용해서 맞는 것
    - 3단계: **가변인자(varargs)**
    - 앞 단계에서 후보를 찾으면 뒷 단계는 보지도 않음. 같은 단계에 후보가 여럿이면 더 구체적인 타입이 이김

    ```java
    void print(int i)       { System.out.println("int"); }
    void print(long l)      { System.out.println("long"); }
    void print(Integer i)   { System.out.println("Integer"); }
    void print(Object... o) { System.out.println("varargs"); }

    print(10);   // "int"

    // print(int)를 지우면    → "long"     (확대 형변환은 1단계, 박싱보다 우선)
    // print(long)까지 지우면 → "Integer"  (2단계 오토박싱)
    // 다 지우면              → "varargs"  (3단계)
    ```

+ 함정: 오버로딩은 **선언 타입**으로 정해짐

    ```java
    static void print(Object o) { System.out.println("Object"); }
    static void print(String s) { System.out.println("String"); }

    Object o = "hello";
    print(o);        // "Object"  ← 실제 객체는 String이지만 선언 타입이 Object
    print("hello");  // "String"
    ```

    - 오버라이딩은 **런타임의 실제 객체**, 오버로딩은 **컴파일 타임의 선언 타입**으로 갈린다

### 오버라이딩 vs 오버로딩 — 조건 비교

| 조건 | 오버라이딩 | 오버로딩 |
|------|-----------|---------|
| 메서드 이름 | 같아야 함 | 같아야 함 |
| 매개변수 목록 | **같아야 함** | **달라야 함** |
| 반환 타입 | 같거나 하위 타입 | 무관 (이것만 다르면 컴파일 에러) |
| 접근 제어자 | 좁힐 수 없음 | 무관 |
| 예외 | checked를 넓힐 수 없음 | 무관 |
| 위치 | 상속 관계 (부모 ↔ 자식) | 같은 클래스 (물려받은 메서드 포함) |
| 결정 시점 | 런타임 — **실제 객체** 기준 | 컴파일 타임 — **선언 타입** 기준 |

### this와 super
+ `this`
    - 현재 객체를 가리키는 **참조**. 필드와 매개변수 이름이 겹칠 때 구분하는 용도로 가장 많이 씀
    - `this(...)`는 같은 클래스의 다른 생성자 호출 (생성자 첫 줄에만)
    - `static` 메서드에는 `this`가 없음 — 객체 없이 호출되므로 가리킬 대상 자체가 없음
+ `super`
    - 부모 클래스의 멤버에 접근하는 **키워드**. `this`와 달리 **참조 변수가 아님**
        + `super`만 따로 떼어 변수에 담거나 인자로 넘길 수 없고, 항상 `super.멤버` / `super(...)` 형태로만 씀
    - `super.method()`는 **동적 바인딩을 건너뛰고** 부모 구현을 직접 호출함
    - `super.super`는 없음 — 조부모 구현을 건너뛰어 부를 수 없음
        + 부모가 자기 규칙을 넣어 재정의해 둔 것을 자식이 우회하지 못하게 막는 것

    ```java
    class Cat extends Animal {
        @Override
        public void speak() {
            super.speak();                        // 부모 동작을 먼저 실행하고
            System.out.println("나비: 야옹~");     // 자기 동작을 덧붙임
        }
    }
    ```

+ 필드는 오버라이딩되지 않음 (**하이딩**)

    ```java
    class Parent { String name = "부모"; }
    class Child extends Parent { String name = "자식"; }

    Child c = new Child();
    Parent p = c;                            // 같은 객체

    System.out.println(c.name);              // 자식
    System.out.println(p.name);              // 부모  ← 선언 타입 기준
    System.out.println(((Parent) c).name);   // 부모
    ```

    - **동적 바인딩은 인스턴스 메서드에만 적용됨.** 필드와 static 메서드는 선언 타입으로 정해짐
    - 부모·자식에 같은 이름의 필드가 있으면 한 객체 안에 필드가 **두 개** 존재함
    - 그래서 필드는 `private`으로 두고 메서드로 열어주는 편이 안전함

### 자주 하는 착각
+ "생성자도 상속된다"
    - 상속되지 않음. `super(...)`로 호출할 수 있을 뿐
+ "오버라이딩은 반환 타입까지 완전히 같아야 한다"
    - 하위 타입이면 됨 (공변 반환 타입)
+ "반환 타입이 다르면 오버로딩이다"
    - 아님. 반환 타입은 시그니처에 포함되지 않아 컴파일 에러
+ "static 메서드도 오버라이딩된다"
    - 하이딩임. 실제 객체가 아니라 선언 타입 기준으로 호출됨
+ "private 메서드를 자식에서 같은 이름으로 다시 쓰면 오버라이딩이다"
    - 자식에게 보이지 않으므로 그냥 새 메서드. `@Override`를 붙이면 컴파일 에러로 잡힘
+ "부모 타입 변수로 접근하면 부모 것이 나온다"
    - **메서드는** 실제 객체 기준으로 자식 것이 실행됨. **필드만** 선언 타입 기준
