## 기본형과 참조형 타입의 차이

### 자바의 기본형 타입
+ 값 자체를 변수에 직접 저장하는 타입
    - 총 8가지이며 모두 소문자로 시작하는 예약어
    - 객체가 아니므로 메서드를 호출할 수 없고 null도 가질 수 없음
+ 정수형 타입
    - byte
        + 8비트
        + -128 ~ 127
    - short 
        + 16비트 
        + -32,768 ~ 32,767
    - int 
        + 32비트 
        + -2,147,483,648 ~ 2,147,483,647
    - long 
        + 64비트 
        + -9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807
    - 정수형은 모두 부호 있는(signed) 타입
        + 자바에는 C의 unsigned 같은 부호 없는 정수형이 없음
        + 기본형 중에서는 char만 예외적으로 부호가 없음
    - 오버플로우가 발생해도 예외가 나지 않음
        + 최댓값에 1을 더하면 최솟값으로 순환함
        + 범위를 넘길 수 있는 계산은 long으로 올리거나 Math.addExact 계열을 사용
+ 실수형 타입
    - float 
        + 32비트 
        + ±3.4E-38 ~ ±3.4E+38
    - double 
        + 64비트 
        + ±1.7E-308 ~ ±1.7E+308
    - IEEE 754 부동소수점 방식이라 값이 정확하지 않음
        + 2진수로 딱 떨어지지 않는 소수는 근사값으로 저장되기 때문
        + 0.1 + 0.2 의 결과가 0.3 이 아니라 0.30000000000000004 가 됨
        + 금액처럼 오차가 허용되지 않는 계산에는 BigDecimal을 사용
+ 논리형 타입
    - boolean 
        + true 또는 false
        + 논리적으로는 1비트지만 실제 크기는 JVM 명세에 정의되어 있지 않음
            - HotSpot 기준으로 boolean 값 하나는 int(4바이트)처럼 다뤄짐
            - boolean 배열은 원소마다 1바이트를 사용
+ 문자형 타입
    - char 
        + 16비트 
        + 0 ~ 65,535 (유니코드)
        + 기본형 중 유일하게 부호가 없는 타입
        + 문자 하나가 아니라 UTF-16 코드 유닛 하나를 담는 것
            - 이모지처럼 코드 유닛 2개(서로게이트 페어)가 필요한 문자는 char 하나로 표현할 수 없음
        + 내부적으로는 숫자이므로 정수처럼 연산됨 ('A' + 1 의 결과는 int 66)
+ 리터럴과 기본값
    - 정수 리터럴의 기본 타입은 int, 실수 리터럴의 기본 타입은 double
        + long 값에는 L, float 값에는 f 접미사를 붙여야 함
        + long big = 10000000000; 은 리터럴이 int로 해석되어 컴파일 에러
    - 필드(인스턴스 변수, static 변수)와 배열 원소는 자동으로 기본값이 채워짐
        + 정수형 0, 실수형 0.0, boolean false, char '\u0000', 참조형 null
    - 지역 변수는 자동 초기화되지 않음
        + 값을 넣지 않고 사용하면 컴파일 에러
        + 스택 프레임은 호출마다 새로 만들어지므로 JVM이 초기값을 보장해 주지 않음
+ 형변환
    - 자동 형변환 (묵시적)
        + 표현 범위가 좁은 타입에서 넓은 타입으로 갈 때는 자동으로 변환됨
        + byte > short > int > long > float > double
        + int/long에서 float/double로 갈 때는 범위는 넓어지지만 정밀도가 손실될 수 있음
    - 명시적 형변환 (캐스팅)
        + 넓은 타입에서 좁은 타입으로 갈 때는 (int) 처럼 직접 표기해야 함
        + 범위를 벗어나는 비트는 잘려나가므로 값이 달라질 수 있음
    - 정수 승격
        + byte, short, char는 산술 연산 시 int로 승격된 뒤 계산됨
        + byte a = 1, b = 2; byte c = a + b; 는 결과가 int라서 컴파일 에러
        + 단 += 같은 복합 대입 연산자는 캐스팅이 내장되어 있어 그대로 통과함
+ Wrapper Class
    - 기본형을 객체 형태로 감싸는 클래스
    - 기본형 타입은 객체가 아니므로, 컬렉션(List, Set, Map)과 같은 참조형이 필요한 곳에서 사용할 수 있도록 제공됨
    - 기본형 타입은 null을 가질 수 없지만 Wrapper Class는 null 가능
        + (Wrapper는 기본형 타입이 아니라 참조형이기 때문에 가능)
    - 참조형이므로 == 는 값이 아니라 주소를 비교함
        + 값 비교에는 equals()를 사용해야 함
    - 값 캐싱 때문에 == 비교 결과가 값의 범위에 따라 달라짐
        + Integer는 -128 ~ 127 범위의 객체를 미리 만들어 두고 재사용함
        + Integer a = 127, b = 127 이면 같은 객체를 가리키므로 a == b 가 true
        + Integer a = 128, b = 128 이면 각각 새 객체라서 a == b 가 false
        + 캐시가 있는 타입: Boolean, Byte, Short, Character, Integer, Long
        + Float, Double은 캐시가 없어 항상 새 객체가 만들어짐
+ 오토박싱(Auto-Boxing)과 오토언박싱(Auto-Unboxing)
    - 오토박싱(Auto-Boxing)
        + 기본형 > Wrapper Class 자동 변환
        + 컴파일러가 Integer.valueOf() 같은 호출로 바꿔주는 문법 설탕
    - 오토언박싱(Auto-Unboxing)
        + Wrapper Class > 기본형 자동 변환
        + 컴파일러가 intValue() 같은 호출로 바꿔줌
    - null인 Wrapper를 언박싱하면 NullPointerException 발생
        + map.get()이 null을 반환하는데 int 변수로 받는 경우가 대표적
    - 반복문 안에서 박싱이 반복되면 객체가 계속 생성되어 성능이 나빠짐
        + 누적 변수는 Long이 아니라 long으로 선언할 것

### 자바의 참조형 타입
+ 참조형 타입
    - 실제 값이 저장된 힙 영역의 주소(참조값)를 저장함
    - 변수는 스택에, 값은 힙에 저장됨
        + 스택은 메서드 실행 중 잠깐 쓰이고 사라지므로 지역 변수 저장에 적합
            - 기본형은 크기가 작고 수명이 짧은 경우가 많아 스택에 넣는게 빠르고 효율적
        + 힙은 크고 유연한 공간이기에 다양한 크기의 객체를 자유롭게 할당할 수 있음
        + 참조형은 여러 곳에서 참조될 수 있고 수명도 길기 때문에 GC가 관리하는 힙에 저장
    - null 값을 가질 수 있음
    - 대표 예시: 클래스, 배열, 인터페이스, 열거형, String, Wrapper 클래스 등
+ "변수는 스택에" 는 지역 변수에 한정된 이야기
    - 인스턴스 필드는 객체 안에 들어 있으므로 참조형 필드의 참조값도 힙에 있음
    - static 변수는 클래스 정보와 함께 Method Area가 관리하는 영역에 저장됨
    - JIT의 이스케이프 분석으로 메서드 밖으로 새어나가지 않는 객체는 힙에 만들지 않고 스칼라 치환될 수도 있음
        + "참조형은 무조건 힙" 은 논리적인 모델이고, 실제 배치는 최적화에 따라 달라짐
+ 하나의 객체를 여러 변수가 함께 가리킬 수 있음
    - 한쪽에서 상태를 바꾸면 다른 쪽에서도 바뀐 값이 보임 (공유로 인한 부작용)
    - 이 문제를 원천적으로 없애는 방법이 불변 객체(immutable)
        + 생성 이후 상태가 바뀌지 않으므로 여러 곳에서 공유해도 안전
        + String, Wrapper 클래스, LocalDate 등이 불변 객체
+ final의 의미가 기본형과 다름
    - 기본형에 final을 붙이면 값 자체를 바꿀 수 없음
    - 참조형에 final을 붙이면 다른 객체를 가리키지 못할 뿐, 객체 내부 상태는 바꿀 수 있음
        + final List list = new ArrayList(); 에서 list.add()는 가능하지만 list에 새 리스트 대입은 불가
+ 배열도 객체
    - new로 생성되어 힙에 저장되고 GC의 대상이 됨
    - 크기는 length 필드로 확인 (String은 length() 메서드라 헷갈리기 쉬움)
    - 원소는 타입별 기본값으로 자동 초기화됨

### == 와 equals()의 차이
+ == 는 변수에 담긴 값을 그대로 비교함
    - 기본형은 값 자체가 들어 있으므로 의도한 대로 값 비교가 됨
    - 참조형은 참조값(주소)이 들어 있으므로 "같은 객체인가"를 묻는 것이 됨
+ equals()는 내용이 같은지를 비교함
    - Object의 기본 구현은 == 와 동일하게 주소를 비교함
    - String, Wrapper 클래스, 레코드 등은 값 비교로 재정의되어 있음
    - 직접 만든 클래스는 재정의하지 않으면 내용이 같아도 false
+ equals()를 재정의하면 hashCode()도 함께 재정의해야 함
    - HashMap, HashSet은 hashCode()로 버킷을 먼저 찾고 그 안에서 equals()로 확인함
    - hashCode()가 다르면 equals()가 true여도 같은 값으로 찾지 못함
+ 문자열 비교에서 == 가 우연히 true가 되는 이유
    - 컴파일 시점에 값이 정해지는 문자열 리터럴은 String Pool에 하나만 만들어 재사용함
    - 같은 리터럴끼리는 같은 객체이므로 == 가 true가 되어버림
    - new String("abc")는 풀과 별개로 새 객체를 만들기 때문에 == 가 false
    - 런타임에 조합된 문자열도 풀에 들어가지 않으므로 == 가 false
    - 우연히 통과하는 경우가 있을 뿐이므로 문자열 비교는 항상 equals()를 사용

### 메서드 인자 전달 방식
+ 자바는 항상 값에 의한 전달(pass by value)
    - 참조형이라고 해서 참조에 의한 전달(pass by reference)이 되는 것이 아님
    - 참조형은 "참조값을 복사해서" 넘기는 것
+ 그래서 이렇게 동작함
    - 기본형: 값이 복사되므로 메서드 안에서 바꿔도 호출한 쪽은 그대로
    - 참조형: 복사본도 같은 객체를 가리키므로 필드를 바꾸면 호출한 쪽에도 반영됨
    - 참조형: 매개변수에 새 객체를 대입하면 복사본이 가리키는 곳만 바뀌므로 호출한 쪽은 그대로

    ```java
    void modify(int num) {
        num = 20;   // 메서드 내에서만 변경됨
    }

    int a = 10;
    modify(a);
    System.out.println(a); // 출력: 10 (원본 값 변경되지 않음)
    // call by value 값 전달 확인
    // 기본형은 값 자체가 복사됨 = 원본 변수의 값이 변경되지 않음

    class Person {
        String name;
    }

    void changeName(Person p) {
        p.name = "John"; // 객체의 필드 값이 변경됨
    }

    Person person = new Person();
    person.name = "Alice";
    changeName(person);
    System.out.println(person.name);
    // 출력: John (객체 내부 값 변경됨)
    // call by reference처럼 보이는 경우 (참조형)
    // 참조형(Reference Type)은 객체의 주소값이 복사됨 = 원본 객체의 필드 값은 변경될 수 있음

    void replace(Person p) {
        p = new Person(); // 복사본이 가리키는 대상만 바뀜
        p.name = "Bob";
    }

    Person target = new Person();
    target.name = "Alice";
    replace(target);
    System.out.println(target.name);
    // 출력: Alice (원본은 그대로)
    // 진짜 call by reference였다면 Bob이 출력되어야 함
    // 참조값이 "복사"되어 넘어간 것이므로 재대입은 호출한 쪽에 영향 없음
    ```

+ 객체를 복사할 때도 같은 문제가 생김
    - 얕은 복사: 참조형 필드는 주소만 복사되어 원본과 같은 객체를 공유함
    - 깊은 복사: 내부 객체까지 새로 만들어 원본과 완전히 분리함

### 정리
+ 저장하는 것
    - 기본형: 값 자체
    - 참조형: 객체가 있는 힙 주소(참조값)
+ 저장 위치
    - 기본형 지역 변수: 스택
    - 참조형이 가리키는 객체: 힙
+ null
    - 기본형: 불가
    - 참조형: 가능
+ 비교
    - 기본형: ==
    - 참조형: equals() (== 는 같은 객체인지 확인할 때만)
+ 기본값 (필드 기준)
    - 기본형: 0, 0.0, false, '\u0000'
    - 참조형: null
+ 메모리 정리
    - 기본형 지역 변수: 스택 프레임이 사라질 때 함께 사라짐
    - 참조형: 참조가 끊어지면 GC가 정리
