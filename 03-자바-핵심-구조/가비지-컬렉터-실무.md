## 가비지 컬렉터 - 실무

### 참조 유형
+ GC는 객체를 회수할지 판단할 때 참조의 강도를 구분함
+ Strong Reference
    - 일반적인 참조 (Object o = new Object())
    - 참조가 살아 있는 한 절대 회수되지 않음
+ SoftReference
    - 메모리가 부족할 때에 한해 회수됨
    - 캐시 구현에 적합함
+ WeakReference
    - 강한 참조가 없으면 다음 GC에서 바로 회수됨
    - WeakHashMap의 키가 이 방식을 사용함
+ PhantomReference
    - 객체가 회수된 뒤 후처리를 수행하기 위한 용도
    - get()은 항상 null을 반환하며, ReferenceQueue와 함께 사용함

### 메모리 누수
+ GC가 있어도 메모리 누수는 발생함
    - GC는 도달 불가능한 객체만 회수하므로, **사용하지 않지만 참조는 남아 있는** 객체는 회수되지 않음
+ 대표적인 원인
    - static 컬렉션에 객체를 계속 담고 제거하지 않는 경우
    - 등록한 리스너나 콜백을 해제하지 않는 경우
    - 스레드 풀 환경에서 ThreadLocal을 remove()하지 않는 경우
        + 스레드가 재사용되면서 이전 작업의 값이 계속 참조됨
    - 클래스 로더가 참조를 붙잡고 있어 언로드되지 않는 경우 (ClassLoader leak)

### 주의할 API
+ System.gc()
    - GC 실행을 **요청**할 뿐이며 강제하지 않음
    - 호출 시 Full GC를 유발할 수 있어 사용을 지양함
    - -XX:+DisableExplicitGC로 호출을 무시하도록 설정할 수 있음
+ finalize()
    - 호출 시점이 보장되지 않고 성능 문제가 있어 JDK 9에서 deprecated, JDK 18에서 제거 대상이 됨
    - 대체 수단
        + 리소스 해제: try-with-resources (AutoCloseable)
        + 정리 작업: Cleaner, PhantomReference

### 확인용 실행 옵션
+ -Xlog:gc
    - GC 발생 시각, 종류, 회수 전후 힙 크기, 소요 시간을 출력 (JDK 9+)
    - 출력 예시
        + [0.325s][info][gc] GC(0) Pause Young (Normal) (G1 Evacuation Pause) 24M->4M(256M) 3.851ms
+ -Xlog:gc*
    - 각 단계별 상세 로그까지 출력
+ 힙 크기
    - -Xms / -Xmx: 힙의 초기 크기 / 최대 크기
    - 두 값을 같게 두면 실행 중 힙 크기 조정으로 인한 변동을 줄일 수 있음
+ 컬렉터 선택
    - -XX:+UseSerialGC / -XX:+UseParallelGC / -XX:+UseG1GC / -XX:+UseZGC
+ 튜닝
    - -XX:MaxGCPauseMillis: 목표 정지 시간 (G1)
    - -XX:MaxTenuringThreshold: Old 승격 age 임계값
+ 분석 도구
    - jstat -gc <pid>: 영역별 사용량과 GC 횟수를 주기적으로 확인
    - jmap -histo <pid>: 클래스별 인스턴스 수와 점유 크기 확인
