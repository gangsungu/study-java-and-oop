## 객체 지향이란

### 객체지향의 정의
+ 객체지향 프로그래밍 (Object-Oriented Programming, OOP)
    - 프로그램을 객체라는 단위로 구성하여 개발하는 프로그래밍 패러다임
    - 객체는 상태(데이터)와 동작(메서드)를 포함하는 독립적인 단위이며 이를 조합하여 프로그램을 구성

### 객체 지향의 특징과 장점
+ OOP의 특징
    - 추상화 (Abstraction)
        + 현실 세계의 복잡한 개념에서 핵심 특징만 추출하여 모델링
        + 동물들에게서 공통적인 '이름', '울음소리' 등을 추출하여 Animal 클래스로 정의
    - 캡슐화 (Encapsulation)
        + 데이터와 메서드를 하나로 묶고, 외부에서 직접 접근하지 못하도록 보호하는 개념
        + 클래스의 변수를 private로 선언하고 getter/setter 메서드를 통해 접근
    - 상속 (Inheritance)
        + 기존 클래스를 기반으로 새로운 클래스를 생성하여 **코드 재사용성**을 높이는 개념
        + Animal 클래스를 상속받아 Dog, Cat 클래스를 구현
    - 다형성 (Polymorphism)
        + 동일한 인터페이스나 메서드를 다양한 방식으로 구현할 수 있는 개념
        + speak() 메서드를 Dog 클래스와 Cat 클래스에서 다르게 구현

        ```java
        // 추상화: 현실 세계의 복잡한 개념에서 핵심 특징만 추출하여 모델링
        abstract class Animal {
            protected String name;

            public Animal(String name) {
                this.name = name;
            }

            // 모든 동물이 소리를 낸다는 공통 개념
            public abstract void speak();
            public void sleep() {
                System.out.println(name + "이(가) 잠을 잡니다.");
            }
        }

        // 상속: 기존 클래스를 기반으로 새로운 클래스를 생성하여 코드 재사용
        class Cat extends Animal {
            // 캡슐화: 데이터를 private으로 보호하고 메서드로 접근 제어
            private boolean isIndoor;

            public Cat(String name, boolean isIndoor) {
                super(name);
                this.isIndoor = isIndoor;
            }

            // 캡슐화: getter/setter
            public boolean isIndoor() {
                return isIndoor;
            }

            public void setIndoor(boolean indoor) {
                isIndoor = indoor;
            }

            // 다형성: 같은 speak() 메서드를 다르게 구현
            @Override
            public void speak() {
                System.out.println(name + ": 야옹~");
            }
        }
        ```

+ 객체지향의 장점
    - 코드 재사용성 증가
        + 상속을 통해 기존 코드를 재사용할 수 있으며 중복 코드 감소
    - 유지보수 용이
        + 캡슐화를 통해 코드 변경시 영향을 최소화
    - 확장성 및 유연성 증가
        + 다형성을 활용하여 코드 변경없이 새로운 기능을 쉽게 구현 가능

### 상속과 생성자 규칙
+ 생성자 호출 순서
    - 자식 객체를 생성할 때는 **부모 생성자가 먼저 완료된 뒤** 자식 생성자가 실행됨
    - 호출은 `자식 → 부모`로 올라가지만, 실제 실행(초기화)은 `부모 → 자식`으로 내려옴 (집을 1층부터 짓는 것과 같음)

    ```java
    class Animal {
        public Animal() { System.out.println("1. Animal 생성자"); }
    }
    class Dog extends Animal {
        public Dog() { System.out.println("2. Dog 생성자"); }
    }
    // new Dog(); 실행 시 출력
    // 1. Animal 생성자
    // 2. Dog 생성자
    ```

+ 자동 super() 삽입 규칙
    - 자식 생성자의 첫 줄에 `super(...)`나 `this(...)`가 없으면, 컴파일러가 **인자 없는 `super()`를 자동으로 삽입**함
    - 이때 부모에 인자 없는 생성자가 없으면 **컴파일 에러** 발생

+ 기본 생성자 자동 생성 규칙
    - 클래스에 생성자를 **하나도 안 쓰면** 컴파일러가 인자 없는 기본 생성자를 자동 생성
    - 생성자를 **하나라도 직접 쓰면** 컴파일러는 더 이상 기본 생성자를 만들어주지 않음

    | 상황 | 인자 없는 생성자 존재? | 자식이 super 생략 시 |
    |------|:---:|:---:|
    | 생성자를 하나도 안 씀 | ⭕ (자동 생성) | 정상 |
    | `Animal(String)`만 직접 씀 | ❌ | **컴파일 에러** |
    | `Animal()` + `Animal(String)` 둘 다 씀 | ⭕ | 정상 |

+ 부모에 인자 없는 생성자가 없을 때 해결 방법
    - ① 부모에 기본 생성자 `public Animal() {}` 추가
    - ② 자식 생성자에서 `super(인자)`로 부모 생성자를 직접 호출
    - ③ 자식 생성자에서 `this(인자)`로 같은 클래스의 다른 생성자를 재활용

    ```java
    class Animal {
        public Animal(String name) { System.out.println("Animal: " + name); }
    }
    class Cat extends Animal {
        public Cat() {
            this("이름 없음");   // ③ 같은 클래스의 Cat(String) 호출
            System.out.println("이름 없는 고양이");
        }
        public Cat(String name) {
            super(name);         // ② 부모 Animal(String) 직접 호출
            System.out.println("이름 있는 고양이");
        }
    }
    ```

    > 핵심: 생성자 첫 줄에는 `super(...)` **또는** `this(...)` 중 하나만 올 수 있고, 아무것도 안 쓰면 `super()`가 자동으로 들어간다.

### 다형성 자세히 보기
+ 업캐스팅 (Upcasting)
    - 부모 타입 변수가 자식 객체를 참조하는 것 (자동으로 이루어짐)
    - 여러 자식 객체를 **부모 타입 하나로 묶어서** 다룰 수 있게 해줌

    ```java
    Animal a = new Cat("나비", true);   // 업캐스팅: Cat → Animal
    List<Animal> zoo = List.of(new Cat("나비", true), new Dog("바둑이"));
    ```

+ 동적 바인딩 (Dynamic Binding)
    - 변수의 **선언 타입(Animal)이 아니라, 실제 객체(Cat, Dog)의 오버라이드된 메서드**가 실행됨
    - 그래서 `for`문에서 `animal.speak()`만 호출해도 각 동물의 소리가 알맞게 나옴

    ```java
    Animal a = new Cat("나비", true);
    a.speak();   // "나비: 야옹~"  ← 선언은 Animal이지만 Cat의 speak()가 실행
    ```

+ 오버라이딩 vs 오버로딩 (헷갈리기 쉬움)

    | 구분 | 오버라이딩 (Overriding) | 오버로딩 (Overloading) |
    |------|------------------------|------------------------|
    | 의미 | 부모 메서드를 **자식이 재정의** | 같은 이름 메서드를 **매개변수 다르게** 여러 개 |
    | 위치 | 상속 관계 (부모 ↔ 자식) | 같은 클래스 안 |
    | 메서드 시그니처 | 이름·매개변수 **동일** | 이름 같고 매개변수 **다름** |
    | 바인딩 시점 | 런타임 (동적) | 컴파일 타임 (정적) |
    | 예시 | `Cat.speak()` 재정의 | `print(int)`, `print(String)` |

+ 다운캐스팅 (Downcasting)과 instanceof
    - 부모 타입을 다시 자식 타입으로 되돌리는 것 (강제 형변환 필요)
    - 잘못된 타입으로 캐스팅하면 `ClassCastException` 발생 → **`instanceof`로 먼저 확인**

    ```java
    Animal a = new Cat("나비", true);
    if (a instanceof Cat) {
        Cat cat = (Cat) a;          // 다운캐스팅
        System.out.println(cat.isIndoor());
    }
    ```

### 추상클래스 vs 인터페이스
+ 추상클래스 (abstract class)
    - **미완성 설계도**: 일부는 구현하고, 일부(`abstract` 메서드)는 자식이 구현하도록 강제
    - 공통 필드(상태)와 공통 메서드를 물려주는 데 적합 → "무엇인가(is-a)" 관계
    - `extends`로 상속하며 **단일 상속만** 가능

    ```java
    abstract class Animal {
        protected String name;          // 상태(필드) 가질 수 있음
        public void sleep() { ... }     // 구현된 메서드
        public abstract void speak();   // 미완성 → 자식이 반드시 구현
    }
    ```

+ 인터페이스 (interface)
    - **규약(계약)**: "이 기능을 할 수 있다"는 행동 명세 → "할 수 있다(can-do)" 관계
    - `implements`로 구현하며 **다중 구현 가능** (여러 인터페이스를 한 클래스가 구현)
    - 자바 8부터 `default`/`static` 메서드로 구현부를 가질 수 있음

    ```java
    interface Swimmable {
        void swim();                    // 추상 메서드 (public abstract 생략됨)
        default void float_() {         // default: 기본 구현 제공
            System.out.println("물에 뜬다");
        }
    }
    class Duck extends Animal implements Swimmable {
        public void speak() { System.out.println(name + ": 꽥꽥"); }
        public void swim()  { System.out.println(name + ": 헤엄친다"); }
    }
    ```

+ 비교표

    | 구분 | 추상클래스 | 인터페이스 |
    |------|-----------|-----------|
    | 키워드 | `abstract class` / `extends` | `interface` / `implements` |
    | 다중 상속/구현 | ❌ 단일 상속만 | ⭕ 다중 구현 가능 |
    | 필드(상태) | ⭕ 인스턴스 변수 가능 | ❌ (상수 `static final`만) |
    | 생성자 | ⭕ 있음 | ❌ 없음 |
    | 목적 | 공통 속성·기능 물려주기 (is-a) | 행동 규약 정의 (can-do) |

+ 언제 무엇을 쓰나
    - 공통 **상태/필드**를 물려주고, 밀접한 계층 관계라면 → **추상클래스**
    - 서로 다른 계층의 클래스에 **공통 행동**만 강제하고 싶다면 → **인터페이스**
    - 헷갈리면: "A는 B이다(is-a)"면 상속/추상클래스, "A는 B를 할 수 있다(can-do)"면 인터페이스
